# База данных

## 1. Назначение

База данных предназначена для хранения информации о пользователях, ресторанах, столах и бронированиях.

## 2. Таблица user

Таблица хранит информацию о зарегистрированных пользователях системы.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `user_id` | Integer | PK, NOT NULL | Идентификатор пользователя |
| `name` | Varchar(100) | NOT NULL | Имя пользователя |
| `email` | Varchar(255) | NOT NULL | Электронная почта |
| `phone` | Varchar(20) | NOT NULL | Номер телефона |

## 3. Таблица restaurant

Таблица хранит информацию о ресторанах.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `restaurant_id` | Integer | PK, NOT NULL | Идентификатор ресторана |
| `name` | Varchar(255) | NOT NULL | Название ресторана |
| `address` | Varchar(255) | NOT NULL | Адрес ресторана |

## 4. Таблица table

Таблица хранит информацию о столах в ресторанах.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `table_id` | Integer | PK, NOT NULL | Идентификатор стола |
| `restaurant_id` | Integer | FK, NOT NULL | Идентификатор ресторана |
| `number` | Integer | NOT NULL | Номер стола |
| `seats` | Integer | NOT NULL, > 0 | Вместимость стола |

## 5. Таблица reservation

Таблица хранит информацию о бронированиях.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `reservation_id` | Integer | PK, NOT NULL | Идентификатор бронирования |
| `user_id` | Integer | FK, NOT NULL | Идентификатор пользователя |
| `table_id` | Integer | FK, NOT NULL | Идентификатор стола |
| `date` | Date | NOT NULL | Дата бронирования |
| `time` | Time | NOT NULL | Время бронирования |
| `guests` | Integer | NOT NULL, > 0 | Количество гостей |
| `status` | Varchar(20) | NOT NULL | Статус бронирования |

Допустимые значения поля `status`:

| Значение | Описание |
|---|---|
| `confirmed` | Бронирование подтверждено |
| `canceled` | Бронирование отменено |

## 6. Связи между таблицами

| Связь | Тип | Описание |
|---|---|---|
| `user` → `reservation` | 1:N | Один пользователь может иметь несколько бронирований |
| `restaurant` → `table` | 1:N | Один ресторан может иметь несколько столов |
| `table` → `reservation` | 1:N | Один стол может участвовать в нескольких бронированиях в разное время |
| `reservation` → `user` | N:1 | Каждое бронирование принадлежит одному пользователю |
| `reservation` → `table` | N:1 | Каждое бронирование связано с одним столом |

## 7. Назначение ключей

PK (Primary Key) — уникальный идентификатор записи в таблице.

FK (Foreign Key) — поле, которое связывает запись с другой таблицей.

Связи между таблицами:

- `table.restaurant_id` → `restaurant.restaurant_id`
- `reservation.user_id` → `user.user_id`
- `reservation.table_id` → `table.table_id`
