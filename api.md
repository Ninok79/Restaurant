# REST API

## 1. Методы API

| Метод | URL | Назначение |
|---|---|---|
| GET | `/restaurants` | Получить список ресторанов |
| POST | `/reservations` | Создать бронирование |
| GET | `/reservations/{id}` | Получить информацию о бронировании |
| PATCH | `/reservations/{id}` | Отменить бронирование |

## 2. GET /restaurants

### 2.1. Описание метода

Метод предназначен для получения списка ресторанов, доступных пользователю.

### 2.2. Атрибутивный состав

Входные параметры отсутствуют.

### 2.3. Алгоритм работы

1. Метод получает запрос на получение списка ресторанов.
2. Backend обращается к базе данных.
3. Backend получает список ресторанов.
4. Backend формирует ответ.
5. Backend возвращает список ресторанов пользователю.

### 2.4. Пример запроса

```http
GET /restaurants
```

### 2.5. Пример успешного ответа

```http
HTTP 200 OK
```

```json
[
  {
    "restaurant_id": 1,
    "name": "Ресторан №1",
    "address": "ул. Ленина, 10"
  },
  {
    "restaurant_id": 2,
    "name": "Ресторан №2",
    "address": "ул. Советская, 25"
  }
]
```

### 2.6. Пример неуспешного ответа

```http
HTTP 500 Internal Server Error
```

```json
{
  "error": 500,
  "description": "Internal Server Error"
}
```

## 3. POST /reservations

### 3.1. Описание метода

Метод предназначен для создания нового бронирования стола в выбранном ресторане.

### 3.2. Атрибутивный состав

Все параметры являются обязательными.

| Атрибут | Описание | Способ передачи | Тип | Пример | Комментарий |
|---|---|---|---|---|---|
| `restaurant_id` | Идентификатор выбранного ресторана | body | Integer | `1` | Ресторан должен существовать |
| `date` | Дата бронирования | body | String | `"2026-08-30"` | Формат `YYYY-MM-DD` |
| `time` | Время бронирования | body | String | `"19:00"` | Формат `HH:MM` |
| `guests` | Количество гостей | body | Integer | `4` | Значение должно быть больше 0 |

### 3.3. Алгоритм работы

1. Метод получает данные бронирования.
2. Система проверяет наличие обязательных параметров и корректность их значений.
3. Система проверяет существование выбранного ресторана.
4. Система ищет в выбранном ресторане свободный стол, вместимость которого не меньше количества гостей, на указанную дату и время.
5. Если подходящий стол найден, система создаёт запись о бронировании в базе данных.
6. Система присваивает бронированию статус `confirmed`.
7. Метод возвращает пользователю информацию о созданном бронировании.
8. Если подходящий стол не найден, система не создаёт бронирование и возвращает ошибку `409 Conflict`.

### 3.4. Пример запроса

```http
POST /reservations
```

```json
{
  "restaurant_id": 1,
  "date": "2026-08-30",
  "time": "19:00",
  "guests": 4
}
```

### 3.5. Пример успешного ответа

```http
HTTP 201 Created
```

```json
{
  "reservation_id": 125,
  "status": "confirmed"
}
```

### 3.6. Примеры неуспешных ответов

#### 400 Bad Request — некорректные или отсутствующие данные

```json
{
  "error": 400,
  "description": "Некорректные данные"
}
```

#### 404 Not Found — ресторан не найден

```json
{
  "error": 404,
  "description": "Ресторан не найден"
}
```

#### 409 Conflict — нет подходящего свободного стола

```json
{
  "error": 409,
  "description": "На выбранное время нет свободных столов"
}
```

## 4. GET /reservations/{id}

### 4.1. Описание метода

Метод предназначен для получения информации о выбранном бронировании.

### 4.2. Атрибутивный состав

| Атрибут | Описание | Способ передачи | Тип | Пример | Комментарий |
|---|---|---|---|---|---|
| `id` | Идентификатор бронирования | URL | Integer | `125` | Бронирование должно существовать |

### 4.3. Алгоритм работы

1. Метод получает идентификатор бронирования.
2. Система ищет бронирование в базе данных.
3. Если бронирование найдено, система получает его данные.
4. Метод возвращает информацию о бронировании пользователю.
5. Если бронирование не найдено, система возвращает `404 Not Found`.

### 4.4. Пример запроса

```http
GET /reservations/125
```

### 4.5. Пример успешного ответа

```http
HTTP 200 OK
```

```json
{
  "reservation_id": 125,
  "restaurant_id": 1,
  "table_id": 5,
  "date": "2026-08-30",
  "time": "19:00",
  "guests": 4,
  "status": "confirmed"
}
```

`table_id` возвращается в ответе, потому что система автоматически назначает стол при создании бронирования.

### 4.6. Пример неуспешного ответа

```http
HTTP 404 Not Found
```

```json
{
  "error": 404,
  "description": "Бронирование не найдено"
}
```

## 5. PATCH /reservations/{id}

### 5.1. Описание метода

Метод предназначен для отмены существующего бронирования.

При отмене запись о бронировании не удаляется из базы данных. Система изменяет её статус на `canceled`.

### 5.2. Атрибутивный состав

| Атрибут | Описание | Способ передачи | Тип | Пример | Комментарий |
|---|---|---|---|---|---|
| `id` | Идентификатор бронирования | URL | Integer | `125` | Бронирование должно существовать |

### 5.3. Алгоритм работы

1. Метод получает идентификатор бронирования.
2. Система ищет бронирование в базе данных.
3. Если бронирование найдено, система изменяет его статус на `canceled`.
4. Метод возвращает результат операции.
5. Если бронирование не найдено, система возвращает `404 Not Found`.

### 5.4. Пример запроса

```http
PATCH /reservations/125
```

### 5.5. Пример успешного ответа

```http
HTTP 200 OK
```

```json
{
  "reservation_id": 125,
  "status": "canceled"
}
```

### 5.6. Пример неуспешного ответа

```http
HTTP 404 Not Found
```

```json
{
  "error": 404,
  "description": "Бронирование не найдено"
}
```
